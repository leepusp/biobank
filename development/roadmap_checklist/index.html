    B3 LIMS: ELN, calendar and registry checklist

    Working list agreed with the lab. Each block must be finished, tested and deployed before the next one starts. [x] done and live, [~] done, waiting for deploy, [ ] open.

    Block A: finish ELN 2.2 (do this before anything else)

    • [x] Advanced search (title:gel and status:completed, extrafield:Medium:TSB)
    • [~] Sharing: read / edit / manage grants for users and research groups (no migration)
    • [~] "Shared with me" filter in the entries dashboard
    • [~] Ownership transfer (to a person who already has access; former author keeps edit; history stays)
    • [x] Categories and statuses per research group, with colours (migration 0098; entry picks the group, coordinator and superusers edit the lists at /internal/lab-tools/notebook/lists/)
    • [x] Editable entry templates (stored in the database: "Save as template" from any entry, shared with nobody, a research group or the lab; manage at /internal/lab-tools/notebook/templates/; built-in templates stay in code)
    • [x] Favourite tags panel and step groups (ELN tags and keywords now use the biobank-wide Tag and Keyword vocabulary; legacy NotebookTag and NotebookEntry.tags are kept for rollback and are to be dropped in a later release)
    • [x] Field builder for extra fields (the visual builder and "Load fields"). A JSON editor was built and then removed on Nov 4: no use for it now; revisit only for import/export between systems.
    • [x] ELN as a hub of the LIMS, part 1: sample, reagent, molecular record and Jupyter notebook pages show a panel "Used in experiments" (links, @-mentions, creation entry), listing only entries the viewer may see (core/services/notebook_backlinks.py).
    • [ ] ELN as a hub, part 2: shipments, collections, storage positions, constructions (with Block D), and the same panel for extra-field references (items, compounds).
    • [x] Review (Nov 4): dashboard filters now include category, group, tag and keyword with removable chips; the cloud became a "Tags and keywords" panel with favourites on top; the to-do and "Steps with deadlines" became one "My tasks" card (tasks can point to an entry); the JSON editor was removed.
    • [~] Rename the stored keys (extra_fields, elabftw.extra_fields_groups) to custom_fields and custom_field_groups. Expand release done in code (read either, write both, data migration 0101, backfill_custom_field_layout command for after a rollback). Contract release open: set WRITE_LEGACY_KEYS = False in core/services/custom_field_layout.py, drop the fallbacks and the old keys once the rollback target no longer needs them.
    • [ ] Gaps found against the reference screens, none built yet: "Draw something" canvas saved as an attachment (2.4), spreadsheet editor polish, compounds search, storage containers on the entry (2.3), exclusive "More" menu actions. Decide each one on use, not on parity.
    • [ ] Browser check of all of the above on production

    Block B: Lab Calendar (new, runs on the existing bench Booking models)

    Today /calendar/ only lists the last 100 sample events. It becomes a real calendar.

    Foundation - [x] Month, week, day and agenda views (FullCalendar 6, MIT, vendored with checksums) - [x] Manage layers: each layer has a name, a colour and a description of what it stands for. Built-in layers (step deadlines, sample events grouped per day and type) are styled per person; custom layers (an instrument, a room, lab meetings) are shared, with booking rules kept optional - [ ] More built-in layers: to-dos, shipments, sample reminders - [x] Create, move and resize bookings in the calendar, with conflict detection and the existing resource rules (rule messages shown in the form, drag reverts on refusal) - [~] Recurring bookings: every N days or weeks, chosen weekdays, ending after N times or on a date; cancel one or the rest of the series. Still open: monthly rules, per-event reminders - [ ] Attendees with accept / decline, and a link from an event to an ELN entry - [x] Dashboard card "Today and this week" (own bookings and step deadlines, shown through an extension panel)

    Google Calendar - [ ] Step 1, no credentials needed: per-user private .ics feed, with a token that can be renewed or revoked, to subscribe from Google Calendar ("From URL"). Needs the LIMS address to be reachable from Google's servers, and Google refreshes subscribed feeds only every several hours. - [x] Step 1: "Add to Google Calendar" button and .ics download on every booking - [ ] Step 2, needs a Google Cloud OAuth client created by the lab: push LIMS events to the user's Google Calendar and keep them updated or removed; optional read of busy times to avoid booking conflicts. Tokens stored encrypted, one-click disconnect. - [~] Export of the view on screen as .ics is done (CSV still open)

    Other useful functions - [ ] Usage report per layer (hours per user and per group) - [ ] Booking approval for restricted equipment, and e-mail notification - [ ] "Find a free slot" for a resource and for a group of people - [ ] Booking templates for common runs (sequencing, qPCR, culture passages)

    Block E: data submissions

Not started; needs a review before any work.
